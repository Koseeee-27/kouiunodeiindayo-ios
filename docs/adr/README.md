# ADR — 技術的な決定の記録

ADR（Architecture Decision Record）は、「何を・なぜ決めたか」を1つの決定につき1ファイルで残す記録。
技術選定の正はここ。ほかのドキュメントに選定理由を重ねて書かない。

## 決まり

- ファイル名は `NNNN-<内容を英語の kebab-case で>.md`。番号は連番
- 状態は次の3つ
  - **提案中**：まだチームで決めていない
  - **採用**：決めた。コードはこれに従う
  - **置き換え済み**：別の ADR で上書きされた（どの ADR かを書く）
- 決定を変えるときは、古い ADR を書き換えない。新しい ADR を足し、古いほうの状態を「置き換え済み」にする
- 1本は短く。比べた選択肢と、外した理由を必ず書く

## テンプレ

```markdown
# NNNN: <決定を一言で>

- 状態：提案中 / 採用 / 置き換え済み（→ NNNN）
- 日付：YYYY-MM-DD

## 決めたこと
## 理由
## 比べた選択肢
## 影響・注意
## 出典
```
