# 実装計画: アルバムの取り込みを速くし、提案を待っている間を見せる

## 概要

アルバムの取り込み（#102）を速くする。1 枚ずつの段ごとの時間をログに出し、写真データの受け取りを 2 枚先まで先に始め、ピッカーが閉じるのを待つ 0.6 秒の間に取り込みを始める。あわせて、仕分けで提案が届くのを待っている写真に「提案を待っています…」を薄く出す。対応する Issue：#120（親 #86）。対応する機能：機能18（取り込み）・機能26（提案）。調べた記録は作業用のメモ（ideas-0927 の 7・7-A。レビュー担当の Claude が書いた）。

main から `feat/120-import-speed` を切って作る。**提案を待っている間の見せ方（手順 4）は #113（問い合わせ直し。`SuggestionService.swift` を触る）のマージ後**。手順 1〜3 は #113 と別のファイルなので先に進めてよい。

**目安：2〜2.5 時間**（ログ 15 分・先読み 45〜60 分・0.6 秒 15 分・待っている間の見せ方 45 分・ドキュメント 15 分）。今（9/27 朝）から 13:00 の Topa'z 投稿までに入れる。

- 7-2：提案を待っている間の見せ方を入れる。チップの行の場所に薄い字で「提案を待っています…」（**文言は仮**。こうせいが実機で見て決める）。失敗して問い合わせをやめたら消す
- 7-3：段ごとの時間のログを入れる
- 7-A-1：受け取りは 2 枚先まで先に始める（同時に 3 本）

## 前提・確認事項

- 取り込み：`Features/Import/PhotoImporter.swift` の `PhotoImportRunner.run` が、1 枚ずつ 受け取り（`loadData` ＝ `item.loadTransferable(type: Data.self)`）→ 縮小・EXIF（`prepare`。裏のスレッド）→ 食事の判定（`labels`。裏のスレッド）→ 保存（`save`。メインスレッド）を直列に行う。最後に `logger.info("取り込み: n 枚 m 秒（…）")`
- 端末の中の処理は Mac で 1 枚 0.09 秒ほど（実機 0.2〜0.4 秒の見込み）。受け取りは 0.2〜0.5 秒、iCloud にしか無い写真は 1〜数秒の見込み（実機の数字はまだ無い）
- ホーム：`Features/Home/HomeView.swift` の `startImport` が、`pickerDismissDelay`（0.6 秒）待ってから取り込みを始める（#102 で、1 枚だけのときに仕分けのカバーが先に出て ✕ がずれた件の直し）
- 提案：`LiveSuggestionService` は、待っている・問い合わせ中の写真の `id` を `pendingIDs` に持つ（#113 で、問い合わせ直しの待ちの間も持ち続ける）。画面からは見えない
- 仕分けのタグの行：`Features/Sort/SortSuggestedTagsView.swift`。提案が無いときも 1 行分の高さを空けている（届いたときにカードが跳ねないように）。その空いた場所に「提案を待っています…」を出せば、カードの大きさは変わらない

## 作り方

### 手順 1：段ごとの時間のログ（`PhotoImporter.swift`）

- `PhotoImportRunner.run` で、1 枚ごとに受け取り・縮小・判定・保存の前後で `ContinuousClock.now` を取り、段ごとの合計と、受け取りの一番長かった 1 枚を控える
- 最後のログに「受け取り 合計 x 秒（最大 y 秒）・縮小 x 秒・判定 x 秒・保存 x 秒」を足す。写真の場所・ラベル・中身は出さない
- テストは要らない（ログだけ）

### 手順 2：受け取りを 2 枚先まで先に始める（`PhotoImporter.swift`）

- 定数 `static var prefetchCount: Int { 2 }`（汎用の型なので `static let` は置けない）
- ループの前に `var loads: [Task<Data?, Error>?]` を用意し、先頭から `prefetchCount + 1` 枚ぶん `Task { try await loadData(item) }` を作る
- 1 枚ごとに `try await loads[index]!.value` で受け取り、受け取ったらすぐ `loads[index] = nil`（データを手放す）にして、`index + prefetchCount + 1` 番目があればそのタスクを作る（同時に動く受け取りは最大 3 本）
- 縮小・判定・保存と、数え方（`failedCount`・`excludedCount`・`importedIDs` の順番）・`onProgress` は今のまま（処理は選んだ順）
- 受け取りの失敗（throw・nil）は今と同じく「読めなかった」に数える
- テスト（`KouiunodeiindayoTests/PhotoImporterTests.swift` に足す）
  - 1 枚目の `loadData` だけ遅らせても、`importedIDs` が選んだ順になる
  - 同時に動く受け取りが 3 本を超えない（`loadData` の中で、動いている数を数える）
  - 今のテスト（受け取りの失敗・nil・進み具合 1/3・2/3・3/3 など）がそのまま通る

### 手順 3：0.6 秒の待ちに重ねる（`HomeView.swift`）

- `startImport` の `try? await Task.sleep(for: Self.pickerDismissDelay)` を取り込みの前から外す。取り込みを始める前に `let started = ContinuousClock.now` を取る
- 取り込みが終わったあと、仕分けのカバーを出す（`importResult` を入れる）前に、`started` から 0.6 秒たっていなければ残りだけ待つ（0 枚のアラートを出すときも同じ）
- コメントを「ピッカーが閉じきる前に仕分けのカバーを出さないよう、カバーを出す前に、始めてから 0.6 秒たつまで待つ（#102）」に
- 確認：1 枚だけ取り込んで、仕分けの ✕ が上にずれない

### 手順 4：提案を待っている間の見せ方（#113 のマージ後）

- `SuggestionService` に `func isPending(_ id: UUID) -> Bool` を足す（待っている・問い合わせ中・問い合わせ直しの待ちなら true。失敗して問い合わせをやめたら false）
  - `LiveSuggestionService` を `@Observable` にし、`pendingIDs` の変化を画面が追えるようにする（`@Observable` にする理由をコメントに。#82 の計画では「画面が変化を見る必要が無い」ので付けなかった）。ほかの状態（待ち行列など）は `@ObservationIgnored`
  - `SuggestionMock`：`disabled` は false、`ramen` などは届くまで true（`delay` の間）。プレビューで「待っている」を見られるよう、ずっと true の `waiting` を足す
- `SortView`：先頭の写真について、`record.suggestedAt == nil && suggestionService.isPending(record.id)` のとき、`SortSuggestedTagsView` に「待っている」を渡す
- `SortSuggestedTagsView`：引数 `isWaiting: Bool` を足す。タグが無く `isWaiting` のとき、空けている 1 行の場所に `Text("提案を待っています…")`（`Theme.font(.subheadline)`・`Theme.textSecondary`。**文言は仮**）。行の高さは変えない。読み上げは「提案を待っています」
- 提案が届いたら（`suggestedAt` が入ったら）文字は消え、点線とチップが出る。問い合わせ直しを使い切ったら `isPending` が false になり、文字は消える（何も出ない。今の「届かなければ出さない」のまま）
- テスト：`SuggestionServiceTests` に「頼むと `isPending` が true、保存したら false、3 回失敗したら false」
- プレビュー：`SortView` に「提案を待っている」（`SuggestionMock.waiting`）を足す

| 操作 | 見るところ |

| 10 枚・30 枚を取り込む（直す前と後） | Xcode のコンソールの「取り込み: …（受け取り 合計 x 秒・縮小・判定・保存）」。受け取りの合計が短くなったか。全体の秒数 |
| iCloud にしか無い写真を混ぜて取り込む | 受け取りの最大の秒数。途中で止まって見えないか |

## リスク

- **受け取りのデータを最大 3 枚持つ**（HEIC 2〜5MB、ProRAW だと数十 MB）。メモリは Debug navigator で見る（#102 の目安 300MB 以内）
- **iCloud のダウンロードを同時に 3 本走らせる**。通信が遅いと 1 本ずつより速くならないこともある。ログで見る
- **`LiveSuggestionService` を `@Observable` にする**と、`pendingIDs` が変わるたびに仕分けの画面が描き直される。先頭の写真の `isPending` だけを読むようにして、描き直しを小さくする
- 「提案を待っています…」が長く出続ける（回数の制限で問い合わせ直しの待ちが長いとき）。#113 の上限（8 秒の間・2 回の問い合わせ直し）で必ず止まる
