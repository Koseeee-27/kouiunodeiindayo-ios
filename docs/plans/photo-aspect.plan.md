# 実装計画: 今日の一枚と仕分けの写真を 3:4 にそろえる

## 概要

ホームの今日の一枚（1:1）と仕分けのカード（画面いっぱい）を、縦長の 3:4（幅 3・高さ 4。iPhone の標準のカメラで縦に構えて撮ったときと同じ）にそろえる。デザイン要件書の「写真の縦横比」（9/24 MTG で決定）の反映。対応する Issue：#57。対応する機能：無し（見た目の反映）。

仕分けの UI の見た目がこの後変わる可能性があるので、#55（カメラから入った仕分けを1枚だけにする）より先にやる。

## 前提・確認事項

- 前の計画は `docs/plans/sort-feel.plan.md`（#36。マージ済みなので書き換えない）。この Issue は、そこで決めた「余りは同じ写真をぼかして敷く」を置き換える。ほかの決まり（写真の縦横比は崩さない・ラベルはカードと一緒に動かさず常に手前・後ろのカードは下端を基準に縮める・スタンプは上端から 96pt）はそのまま守る
- 一覧・ホームの最近の写真は正方形のまま。記録の詳細は今も 3:4（見た目は変えない）
- `project.pbxproj` は触らない。ファイルは増やさない
- 決めたこと（2026-09-25 にこうせいと確認済み）
  - **3:4 の値は `Theme.photoAspectRatio`（`3.0 / 4.0`）の1か所に置く。** 仕分け・今日の一枚・詳細から使う
  - **仕分けカードの横長の写真は、3:4 のカードに `scaledToFit` で収め、上下の余白は無地（カードの地 `Theme.surface`）にする。ぼかしの地はやめる。** 縦の写真はカードいっぱいに入るので、余白が出るのは横長（アルバムから選んだものなど）のときだけ
  - **ホームはスクロールしない設計にする。** ふだんの文字サイズで、開いたら今日の一枚・仕分け待ちの帯・最近の写真まで1画面に収める。今日の一枚は「残りの高さに 3:4 で収まる大きさ（上限は横幅いっぱい）」で左右の真ん中。文字サイズが大きいときなど入り切らない場合だけスクロールする
  - **今日の一枚の写真は、今のまま枠いっぱいに広げて切り抜く**（横長は左右が切れてよい）

## ステップ

1. `Kouiunodeiindayo/Design/Theme.swift` — `static let photoAspectRatio: CGFloat = 3.0 / 4.0` を足す（「仕分け・今日の一枚・詳細で使う。一覧は正方形」とコメント）
2. `Kouiunodeiindayo/Features/Sort/SortCardView.swift` — ぼかしの `overlay` を消し、`Theme.surface` の上に `scaledToFit` の写真1枚だけにする。先頭コメントを「3:4 のカード。縦の写真はいっぱい、横長は上下が無地」に。プレビューの frame を 360×480 に
3. `Kouiunodeiindayo/Features/Sort/SortCardStackView.swift` — カードの `ZStack` の `.frame(maxWidth: .infinity, maxHeight: .infinity)` を `.aspectRatio(Theme.photoAspectRatio, contentMode: .fit)` に替える
   - **ラベルの `overlay` より前に付ける**（後だとラベルが場所全体の縁に残ってカードから浮く）。`cardStack` の中で付ければ、`sortArea` の `overlay` はその後に付く
   - 後ろのカードののぞき（`.padding(.bottom, SwipeDirection.backCardPeek)`）はラベルの外側のまま
   - 全体を上下左右の真ん中に置くのは、`body` の `.frame(width:height:)`（既定で真ん中）がそのまま受け持つ（確定版ワイヤーと同じ）
   - 飛ばす先の計算は `GeometryReader` の大きさのまま（カードが小さくなった分、少し遠くまで飛ぶだけで、画面の外に出きることは変わらない）
4. `Kouiunodeiindayo/Features/Home/HomeView.swift` — 今日の一枚を `Theme.photoAspectRatio` にし、1画面に収める（下の「実装して分かったこと」）。「3:4 にそろえるのは #57」のコメントを消す
5. `Kouiunodeiindayo/Features/Detail/RecordDetailView.swift` — `3 / 4` を `Theme.photoAspectRatio` に（見た目は変えない）
6. 検証：`docs/rules/verification.md` どおり
   - プレビュー：仕分けの「1枚・複数枚・横長の写真・ドラッグ途中・幅 375pt」、ホームの全プレビュー（SE 相当・大きい機種）
   - 見るところ：ラベルがカードの縁に付いている／スタンプ（上端から 96pt）が変に見えない／上のラベルと「う、うまい」が 375pt で重ならない／写真が引き伸ばされずぼかしも無い／ホームがスクロール無しで収まる

## 実装して分かったこと（2026-09-25）

- **ホームの大きさの決め方は `ViewThatFits(in: .vertical)` にした。** 「1画面に収める版」と「`ScrollView` に入れた版」の2つを並べ、入るほうを出す
  - 1画面に収める版では、今日の一枚に `.layoutPriority(1)` を付けて、ほかの要素より先に残りの高さを受け取らせる。写真は `.aspectRatio(3:4, .fit)` なので、残りの高さと横幅のどちらか小さいほうで大きさが決まる（横幅いっぱいが上限）。余った高さは一番下の `Spacer` が受け取る
  - `ViewThatFits` は子の「理想の大きさ」で入るかどうかを比べる。写真の理想の高さは横幅 × 4/3 なので、そのままだと小さい画面でいつもスクロール版になる。1画面に収める版では、写真に `.frame(minHeight: 200, idealHeight: 200)` を付け、「写真が 200pt 取れるなら収まる」として比べさせた。200pt は `HomeView.todayPhotoMinHeight`
  - 大きさを測って `@State` に入れる方法（`onGeometryChange` など）は採らなかった。測る → 描き直す、の2回の描画が要り、最初の1フレームで写真が大きく出てから縮むおそれがあるため
  - 高さで大きさが決まって横幅より細くなった写真は、`.frame(maxWidth: .infinity)` で左右の真ん中に置く（`Button` の外に付けるので、押せる範囲は写真だけ）
  - 確かめた結果：SE 相当（幅 375pt・高さ 647pt。ステータスバー 20pt を除いた大きさ）で写真の高さ約 229pt、iPhone 18 Pro・18 Pro Max でも1画面に収まる。SE 相当・文字サイズ XXX Large ではスクロール版（写真は横幅いっぱいの 3:4）になる
  - SE のシミュレータが手元に無いので、`HomeView` に「SE 相当」のプレビュー（`RootView` を `.frame(width: 375, height: 647)` で出す。下タブも入る）を2つ足した
- **仕分けカードの横長の写真の余白は無地（`Theme.surface`）にした**（上の「決めたこと」のとおり）。#36 のぼかしの地は消した。写真とカードの地を別々の `overlay` にする理由（`scaledToFill` の地がカードの大きさを乗っ取る）は、ぼかしが無くなったので無くなった
- 仕分けのカードは、手元の機種（幅 375〜440pt）ではどれも横幅で大きさが決まり、上下に画面の地が空く

## リスク

- 3:4 のカードは画面いっぱいより小さいので、スワイプの手触り（`commitDistance` などのしきい値はカードの大きさに依らない pt の値）とラベルの位置の感じ方が変わる。実機で確かめる（こうせい）
- 今日の一枚の最小 200pt は、SE 相当でぎりぎりではない（約 229pt）が、仕分け待ちの帯と最近の写真が両方あるときの値。帯の文言や最近の写真の大きさが変わったら、SE 相当のプレビューで見直す
