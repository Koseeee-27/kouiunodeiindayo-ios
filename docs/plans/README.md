# plans — 実装計画（タスクの受け渡し単位）

実装計画をここに置く。ファイル名は `<機能名>.plan.md`。どの AI ツールで作ってもよい。

- **plan は開発者間のタスク受け渡し単位**。書いた人と実装する人が別でもよい
- 実装を引き継ぐときは、新しいセッションでこのファイルのパスを渡すだけでよい
- 実装が終わった plan は先頭に `> ✅ 実装済み` を付けて残す（消さない。後から経緯を追える）

## フォーマット

```markdown
# 実装計画: <機能名>

## 概要
（何を作るか1〜2行。対応する Issue：#番号。対応する機能番号：`docs/requirements.md` の機能n）

## 前提・確認事項
（不明点・仮定があれば）

## ステップ
1. `path/to/file` — 作業内容 / 確認方法
2. ...

## リスク
- （ハマりそうな箇所と回避策）

## 完成の確認方法
- （動作確認の手順。実機での確認が要るかどうか）
```

計画は「別の開発者（の AI）がこのファイルだけ読んで実装を引き継げる」レベルの具体性にする。
